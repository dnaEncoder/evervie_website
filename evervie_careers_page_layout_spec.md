# Evervie Careers Page
## Visual Layout and Content Specification

## 1. Page Purpose

The Careers page should introduce Evervie as a meaningful place to work, explain the kinds of opportunities available, and give candidates a clear way to discover and apply for open roles.

The primary user journey is:

```text
Understand Evervie’s career proposition
→ Learn what working at Evervie can offer
→ Search or filter open positions
→ Open a role
→ Apply or submit interest
```

The page should remain simple, credible, and easy to navigate. It should not feel like a large recruitment portal unless the number of vacancies later requires one.

---

## 2. Overall Page Flow

```text
Global Header
Breadcrumb
Career Hero
Opportunities at Evervie
Open Positions
Closing Recruitment CTA
Global Footer
```

The page begins with the broader reason to join Evervie and then moves quickly into available roles.

---

## 3. Global Header

Use the existing Evervie website header.

The **Careers** navigation item should appear active.

Recommended breadcrumb:

```text
Home / Careers
```

The breadcrumb should align with the main page container.

---

## 4. Career Hero

### Overall layout

Use a wide two-column hero:

```text
[ Left career introduction ]      [ Right illustrative visual ]
```

The left side introduces the page and contains the primary action.

The right side contains a simple illustration or abstract visual that represents people, progress, healthcare, and future opportunity.

### Left content area

Include:

```text
Eyebrow
Large headline
Supporting paragraph
Primary CTA
```

Suggested structure:

```text
CAREERS

Building a healthier
tomorrow, together

At Evervie, we are creating lasting impact across healthcare. Join a team of people committed to innovation, excellence, collaboration, and better outcomes.

Explore Opportunities
```

The headline should be the dominant element and may be split across two lines.

The supporting paragraph should remain concise and should explain:

- The broader healthcare mission
- The opportunity to contribute meaningfully
- The collaborative nature of the organisation
- The possibility of long-term professional growth

### Hero CTA

Primary action:

```text
Explore Opportunities
```

The action should scroll the user to the Open Positions section.

### Right visual area

The visual can include:

- A small group of people facing a healthcare-oriented future landscape
- A pathway moving toward healthcare institutions or communities
- A rising sun or circular symbol
- Light line-based city, hospital, or care-environment elements
- Subtle Evervie visual-language shapes

Avoid using a literal office-team stock photograph.

The visual should support the idea of collective progress and future healthcare impact without introducing unnecessary detail.

---

## 5. Opportunities at Evervie

### Section role

This section explains the kinds of professional value and working experiences Evervie can offer.

It should answer:

```text
Why should someone consider working at Evervie?
```

### Section introduction

Use a centred heading and short supporting statement.

Suggested copy structure:

```text
Opportunities to make a difference

We are building the future of healthcare through innovation, collaboration, and a shared commitment to better outcomes.
```

### Opportunity layout

Use four evenly distributed modules across the page:

```text
[ Innovative Environment ]
[ Collaborative Culture ]
[ Career Growth ]
[ Global Impact ]
```

Each module contains:

```text
Simple icon
Short heading
One- or two-line description
```

### Suggested content

#### Innovative Environment

```text
Work on meaningful challenges that can create real-world healthcare impact.
```

#### Collaborative Culture

```text
Be part of a diverse team that values ideas, expertise, and different perspectives.
```

#### Career Growth

```text
Develop your skills, take on responsibility, and grow with an evolving healthcare platform.
```

#### Global Impact

```text
Contribute to building more accessible and dependable healthcare across communities.
```

### Layout behaviour

The four modules should read as one connected opportunity system rather than four unrelated promotional cards.

Use consistent alignment, spacing, and icon placement.

On smaller screens, the modules can become a two-column grid or stack vertically.

---

## 6. Open Positions

### Section role

This is the functional centre of the page.

It should allow candidates to quickly search, filter, and open available roles.

### Section header

Use a two-part heading row:

```text
[ Open Positions heading and introduction ]   [ Filters and search ]
```

Suggested copy:

```text
Open Positions

Explore current opportunities and find your next chapter at Evervie.
```

### Filters and search

Recommended controls:

```text
Department filter
Location filter
Search jobs
```

Optional controls can include:

```text
Employment type
Work arrangement
Experience level
```

Only include filters that are useful for the available role volume.

### Job listing structure

Use a clean vertical list rather than a grid of large job cards.

Each row should contain:

```text
Role icon
Job title
Department
Location
Employment type
Directional arrow
```

Example layout:

```text
[ Icon ] Senior Investment Analyst
         Investments

                                  Mumbai, India
                                  Full-time        →
```

### Job row behaviour

The full row should be clickable.

Selecting a row should open the relevant job-detail page.

Use dividers between roles so the list remains easy to scan.

Do not add long job descriptions to the listing page.

### Empty and low-volume states

When only a small number of jobs are available, the section should remain balanced without adding placeholder roles.

When no roles are available, display:

```text
There are currently no open positions.

You may still share your profile with our talent team for future opportunities.
```

Possible action:

```text
Submit Your Profile
```

### View all action

When the page previews only a limited number of vacancies, place a centred action below the list:

```text
View All Opportunities
```

If every available role is already displayed, this action can be omitted.

## 7. Job Detail Page Requirements

Each role should link to a dedicated job-information page.

The detail page may include:

```text
Job title
Department
Location
Employment type
Work arrangement
Experience level
Date posted
Application deadline
Role overview
Responsibilities
Required qualifications
Preferred qualifications
What Evervie offers
Equal-opportunity statement
Apply action
Share role
Related openings
```

The application action may lead to:

- An internal application form
- A recruitment platform
- An email application route
- A connected HR system

Only display information that exists for the role.

---

## 8. Closing Recruitment CTA

Near the bottom of the page, include a wide closing recruitment section.

### Layout

```text
[ Closing heading and supporting copy ]       [ Recruitment CTA ]
```

Suggested copy:

```text
Ready to make an impact?

We are always looking for passionate people who want to help shape a healthier tomorrow.
```

Suggested action:

```text
Join Our Team
```

The action may link to:

- All open positions
- A general application form
- The talent-team contact route

The section should act as a final invitation rather than repeating the full job list.

## 11. Interaction Notes

### Explore Opportunities

- Scrolls smoothly to the Open Positions section.
- The destination should receive visible focus for accessibility.

### Filters

- Updating a filter refreshes the visible job list.
- Multiple filters may be combined.
- Provide a clear reset option when filters are active.

### Search

Search can match:

- Job title
- Department
- Location
- Role keywords

### Job rows

- The full row acts as one clear target.
- The arrow reinforces forward navigation.
- Keyboard users should be able to open each role.

### Application

- Clearly distinguish between viewing a role and applying.
- Application should not begin unexpectedly from the listing row.
- The job-detail page should provide the primary Apply action.

---

## 12. Responsive Behaviour

### Desktop

```text
Two-column hero
Four opportunity modules in one row
Open-position heading with filters beside it
Horizontal job rows
Wide closing CTA
```

### Tablet

```text
Hero remains split where space allows
Opportunity modules become two columns
Filters wrap onto a second line
Job metadata remains horizontally aligned where possible
```

### Mobile

Stack the page vertically:

```text
Header
Breadcrumb
Hero copy
Hero visual
Opportunity modules
Open Positions heading
Search
Filter controls
Job rows
Closing CTA
Footer
```

On mobile:

- Opportunity modules stack or display in two columns.
- Filter controls can open inside a drawer or bottom sheet.
- Job-row metadata should move below the title.
- Long job titles must wrap naturally.
- The closing CTA should stack its copy and action vertically.

---

## 13. Content Behaviour

The layout should adapt to the available information.

- Roles without a department should not leave empty spacing.
- Remote or hybrid roles should display their work arrangement clearly.
- Closed roles should no longer appear in the active vacancy list.
- Roles with application deadlines should show them on the detail page.
- Long location names should wrap without affecting the arrow alignment.
- The number of opportunity modules can reduce if Evervie approves fewer themes.
- Generic or future-interest applications should be clearly separated from active vacancies.

---

## 14. Backend Content Note

All job information—including titles, departments, locations, employment types, descriptions, requirements, application links, posting dates, and vacancy status—should be populated dynamically from the existing backend, CMS, or recruitment system.

The frontend should define only:

- Page structure
- Opportunity presentation
- Search and filtering
- Job-list presentation
- Responsive behaviour
- Loading, empty, and error states

No job-specific information should be hardcoded into the frontend.
